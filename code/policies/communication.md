# Policy — Communication

## 1. Plain language, progressive questions, problem before solution

**Mirror the person.** Calibrate how technical to be only from this conversation: the words they
use, and whether a term you introduced landed. Default to business language. Never infer it from
role, title, name, or company.

**Ask 2–3 questions per batch**, shape the next batch from the answers, and stop when answers stop
opening new areas. Never send the whole questionnaire — you get a filled-in form instead of the one
answer that mattered.

**Problem before solution.** When someone arrives with a solution, record it, then ask what problem
it solves. The problem is the requirement; the solution is one proposal.

**One decision per question.** When you need a person to decide, state the decision, the options,
and what each option costs — then wait. Don't bury a decision inside a status report.

Conversation language is Thai (`policies/documentation.md` §6); plain language means plain Thai.
