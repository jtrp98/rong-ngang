# REQ-019 — Blocker: ขอแก้ design / requirement ระหว่างทำ task

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น

## กติกาทางธุรกิจ

- engineer เจอปัญหา design → รายงาน `BLOCKED / DESIGN_CHANGE_REQUIRED` (Task, Reference DES, Reason) → system-analyst แก้ design → project-manager เช็ค impact/แก้ plan → engineer task ที่กระทบเดินต่อ
- เจอปัญหา requirement → `REQUIREMENT_CHANGE_REQUIRED` → business-analyst แก้ → system-analyst ถ้าจำเป็น → project-manager replan ถ้าจำเป็น
- engineer ไม่แก้ design/requirement เอง (ownership เดิม — REQ-003) · การแก้ที่เป็น business choice สำคัญยังผ่าน human gate 1 ตามเดิม
- task ที่ไม่อยู่ใน impact ที่ PM ระบุ รันต่อตาม Depends ได้
- ชื่อ state ในข้อนี้เทียบเท่า `NEEDS_DESIGN_CHANGE` / `NEEDS_REQUIREMENT_CHANGE` ใน REQ-021 — รูปที่ใช้จริงให้ SA กำหนดใน contract

- **AC-062** — engineer รายงาน design blocker พร้อม Task, Reference DES, Reason → task นั้นหยุด และงานถูกส่งให้ system-analyst โดยไม่ต้องมีคนสั่ง; หลัง SA แก้ → PM → task ที่ PM ระบุว่ากระทบถูก dispatch ใหม่
- **AC-063** — requirement blocker ถูกส่งให้ business-analyst ก่อนเสมอ (ไม่ไป SA/PM ก่อน)
- **AC-064** — ระหว่างรอ blocker ถูกแก้ task ที่ไม่อยู่ใน impact ยังรันต่อ (dashboard เห็น running)
