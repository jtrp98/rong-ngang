# REQ-001 — หน้าจอเปิดมี 2 กรณี: งานที่เริ่มแล้ว และงานใหม่

Web UI แบบ local (localhost ของเครื่องนี้) เปิดมาไม่มีช่องสั่งงานอิสระ — มี 2 กรณี: **(1) งานที่เริ่มไปแล้ว/ทำต่อจากของเดิม** — เลือก knowledge และ module ได้ ระบบแสดงสถานะว่างานนี้ถึงไหนแล้ว (ขั้นถัดไปของ pipeline, task ค้าง, `## Waiting on Human`) และมีปุ่มเริ่มงาน **(2) งานใหม่** — มีช่องพิมพ์ข้อความ กดส่งแล้วส่งตรงถึง business-analyst (REQ-007)

ถ้า module ที่เลือกมี `## Waiting on Human` ค้างอยู่ การกดปุ่มเริ่มงานจะพาไปหน้าตอบ gate ก่อน ไม่เริ่มงานใหม่ทับ — ปิด OQ-5 ตาม default (2026-10-04)

- Source: ผู้ใช้ (คำตอบคำถาม BA 2026-10-04: Web UI แบบ local + ข้อความแก้ไขเรื่อง 2 กรณี) · Confirmed by: ผู้ใช้ · Status: confirmed
- **AC-001** — เปิด Web UI ที่ localhost เห็นสองกรณีครบ: ส่วนเลือกงานเดิม (knowledge/module) และช่องพิมพ์งานใหม่
- **AC-002** — เลือก knowledge/module แล้วเห็นสถานะล่าสุดของงานตรงกับเอกสารจริงใน knowledge (ขั้นถัดไป, task ค้าง, Waiting on Human)
- **AC-003** — กดปุ่มเริ่มงานแล้ว pipeline วิ่งต่อจากขั้นล่าสุดของ module นั้น โดยผู้ใช้ไม่ต้องพิมพ์บริบทซ้ำ
