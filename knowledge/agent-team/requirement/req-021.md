# REQ-021 — กติกาเดิน workflow แบบ deterministic, output state, localized retry

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น

## กติกาทางธุรกิจ

agent จบด้วย output state แบบ structured หนึ่งค่า: `DONE`, `PASS`, `FAIL`, `BLOCKED`, `NEEDS_DESIGN_CHANGE`, `NEEDS_REQUIREMENT_CHANGE`, `NEEDS_HUMAN` (รายละเอียดเท่าที่จำเป็น)

กติกาเปลี่ยนขั้น — **ตัดสินด้วย code ไม่ใช้ LLM**:

| ผล | ขั้นถัดไป |
|---|---|
| review FAIL | กลับ task owner |
| review PASS | QA |
| QA PASS | orchestrator mark `verified` จาก verdict ของ qa-engineer (REQ-011) |
| QA FAIL | defect packet กลับ owner (REQ-016) |
| Depends ไม่ครบ / ครบ | run ไม่ได้ / runnable |
| design blocker | system-analyst (REQ-019) |
| requirement blocker | business-analyst (REQ-019) |
| เกิน retry limit | human (gate 4) |
| แถว plan Owner reviewer/security | ไม่ dispatch + แจ้งคน (AC-079) |

- **Localized retry:** task ที่ fail ถูก retry เฉพาะตัวมัน — ไม่ rerun task อื่นที่ไม่กระทบ · propagate impact เฉพาะเมื่อจำเป็น
- ห้าม agent loop ไม่จำกัด — **retry limit = กติกาเดิม** (OQ-11 — เจ้าของ jtrp98 2026-10-05):
  - fix round ได้ 2 รอบต่อ task, รอบที่ 3 ที่ fail ขึ้น gate 4 — ค่า config ตั้งต้น 2 (ที่มา: `CLAUDE.md` finish rules)
  - review FAIL และ QA FAIL ใช้ตัวนับเดียวกันต่อ task · Feature QA FAIL ที่ระบุ task ได้ นับเข้า task นั้น
  - session crash ไม่นับ (REQ-020)

- **AC-068** — handoff ที่ไม่มี output state หนึ่งใน 7 ค่า → ระบบไม่เดินต่อและแจ้งให้คนเห็น
- **AC-069** — ทุกแถวในตารางข้างบน: input เดียวกันได้ขั้นถัดไปเดียวกันทุกครั้ง และไม่มีการเรียก LLM เพื่อเลือกขั้นถัดไป (ตรวจด้วย test/log)
