# REQ-012 — 1 coherent task = 1 session (Agent ≠ Session)

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น

## กติกาทางธุรกิจ

- Agent = prompt + tools + permissions + workflow rules — agent หนึ่งตัว spawn ได้หลาย session
- default: **1 coherent task = 1 session** — inspect → implement → test → fix → finish จบใน session เดียว · default worker packet = **task เดียว**
- multi-task worker session ได้เฉพาะเมื่อครบทุกข้อ: owner เดียวกัน, dependency boundary เดียวกัน, contract เดียวกัน, context overlap สูง, review และ rollback ร่วมกันได้ (เช่น งานเล็กใน endpoint เดียว) — PM จัดกลุ่มไว้ใน plan, orchestrator ตรวจเกณฑ์เชิงกลไก (owner เดียวกัน, Depends เข้ากันได้) · default = ไม่รวม (OQ-12)
- กฎเลือก session: same goal + task + local context → session เดิม · task ต่างกัน → worker session ใหม่ · reviewer/QA → clean session ใหม่ (REQ-015, REQ-016) · task ใน plan = งานของ role ที่ไม่ใช่ reviewer/security (REQ-011)
- Session policy ต่อ role: BA = 1 feature/change · SA = 1 design/change-impact · PM = 1 planning/replanning op · test-planner = 1 feature/test-strategy scope · FE/BE = 1 task · reviewer = 1 clean session ต่อ small execution wave · QA = 1 clean session ต่อ QA round/task batch · security = 1 audit scope (stage ท้าย phase ที่มี 🔒 — ไม่ใช่ task ใน plan, OQ-20) · devops = 1 release/deployment
- รอบแก้ (fix) หลัง review/QA FAIL เปิด **session ใหม่** ที่ได้ defect packet + artifact เท่านั้น — "session เดิม" ใช้ภายใน attempt เดียว · resume session เดิม → backlog (OQ-18)

- **AC-041** — packet ของ worker session มี task id เดียวโดย default; packet ที่มีหลาย task ปรากฏเฉพาะเมื่อ task ทั้งหมดมี owner เดียวกันและPM จัดกลุ่มไว้ใน plan และ orchestrator ตรวจเกณฑ์เชิงกลไกผ่าน; รอบแก้ของ task ได้ session id ใหม่ทุกรอบ
- **AC-042** — BA/SA/PM/test-planner/security/devops แต่ละ session ทำงานขอบเขตเดียวตาม session policy ข้างบน — ดูจาก log ว่า session หนึ่งไม่ข้ามไปทำ feature/release อื่น
