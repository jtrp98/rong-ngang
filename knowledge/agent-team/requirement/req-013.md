# REQ-013 — รัน task ที่อิสระกันพร้อมกัน (parallel) และ unlock ตาม contract

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น

## กติกาทางธุรกิจ

- task ที่ Depends ครบและไม่ขึ้นต่อกัน รันพร้อมกันได้ (เช่น BE-001, BE-002, FE-001)
- FE task ที่ขึ้นกับ contract ที่ BE task ผลิต ถูก unlock เมื่อ BE task นั้น **เสร็จจริง** เท่านั้น — ห้าม FE เดา contract คู่ขนานกับ BE · FE task ที่ไม่เกี่ยวกับ contract นั้นรันคู่ขนานได้
- "เสร็จจริง" = BE task มีสถานะ `verified` ใน `plan\index.md` (OQ-10 — เจ้าของ jtrp98 2026-10-05)
- จำนวน session ที่รันพร้อมกันมีเพดาน **ค่าเดียวทั้งระบบ** ใน config ค่าตั้งต้น 3 (ค่า 3 — สมมติฐาน — ยังไม่ยืนยัน) · เพดานต่อ camp/ต่อ role ไม่อยู่ใน R1 → backlog (OQ-10)
- **แก้ข้อกำหนดเดิม:** เดิม pipeline เดินทีละ stage (driver invoke subagent ถัดไปทีละตัว — `CLAUDE.md` §The pipeline และ `scope.md` Constraint "กติกา pipeline ของ sta2 ใช้เหมือนเดิม") → orchestrated mode เปลี่ยนเป็นรัน task ที่ runnable พร้อมกัน · solo mode (REQ-008 "สวม role ทีละตัว") คง serial — parallel เป็นของ orchestrated mode เท่านั้น (OQ-17)

- **AC-043** — task สองตัวที่ Depends ครบและไม่ขึ้นต่อกัน ถูก dispatch โดยไม่รอกันจบ — dashboard เห็นทั้งสองเป็น running พร้อมกัน
- **AC-044** — FE task ที่ Depends ถึง BE task ไม่ถูก dispatch จนกว่า BE task นั้นเป็น `verified`; FE task อื่นที่ไม่ขึ้นกับ BE นั้นรันระหว่างนั้นได้
