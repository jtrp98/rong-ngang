# REQ-022 — แจกจ่าย rong-ngang เป็น npm package

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น · กระทบ: **pack + orchestrator** (R2)

## กติกาทางธุรกิจ

rong-ngang (pack: role prompts, policies, templates, prompts + orchestrator) ถูกแจกจ่ายให้ project ปลายทางเป็น **npm package** — ไม่ใช่การ copy โฟลเดอร์สินค้าลง project. ตัวสินค้าใน repo นี้ (`workspace\`) คือ source ของ package. role prompts / policies / templates **มากับ package อย่างเดียว** — project ปลายทางแก้หรือ override ไม่ได้; เปลี่ยนได้โดยอัปเดต version ของ package เท่านั้น

ปัญหาที่แก้ (เจ้าของเลือกครบ 4 ข้อ): อัปเดตทีมง่ายไม่ทับ config · project สะอาด · ใช้หลาย project บนเครื่องเดียว · แยกของสินค้ากับของ project ชัด

- Source: เจ้าของ (jtrp98) ในแชท 2026-10-08 — "ไม่ใช่สำเนา แต่เป็น ของที่จำเป็น อาจจะติดตั้งเป็น npm ก็ได้ เอาไว้เก็บ พวก config อะไรทำนองนี้" + AskUserQuestion 2026-10-08: การแจกจ่าย = "npm package (ยืนยัน)", pack = "มากับ package อย่างเดียว" · Confirmed by: เจ้าของ (jtrp98) · Status: confirmed
- ชื่อ package และ registry (public / private) ยังไม่กำหนด — (สมมติฐาน — ยังไม่ยืนยัน) ให้ design เสนอ
- ยังไม่มี project ที่ใช้ rong-ngang จริง → **ไม่ต้อง migrate** · schoolbright จะเป็น project แรก (เจ้าของ 2026-10-08)
- **AC-081** — ติดตั้ง rong-ngang ลง project ได้ด้วยคำสั่ง npm โดยไม่ต้อง copy source ของ orchestrator หรือ pack ลง project เอง
- **AC-082** — role prompts, policies, templates ที่ทีมใช้ใน project มาจาก package ที่ติดตั้งเท่านั้น — ไม่มีไฟล์เหล่านี้ใน `<project>\rong-ngang-workspace\` และวางไฟล์ชื่อเดียวกันไว้ใน project แล้วระบบไม่หยิบไปใช้แทน
- **AC-083** — อัปเกรด rong-ngang เป็น version ใหม่ด้วยคำสั่ง npm แล้ว ไฟล์ใน `<project>\rong-ngang-workspace\` (การผูก, override, state/log) และเอกสารใน `<project>\knowledge\` ยังอยู่ครบ ไม่ถูกเขียนทับ
- **AC-084** — package ที่ publish ไม่มี path ของเครื่องผู้พัฒนาหรือชื่อ project ใดฝังอยู่
