# REQ-020 — Orchestrator เป็นเจ้าของ runtime state (แยกจาก project state)

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น

## กติกาทางธุรกิจ

- orchestrator (TypeScript) เป็น runtime workflow controller และเจ้าของ runtime state: task ไหนรัน/เสร็จ/blocked, retry รอบไหน, session ไหนเป็นของ task ไหน, dependency unlock — **ไม่ให้ long-lived LLM main session เป็นคนจำ**
- **Project state** (artifact: Status ใน `plan\index.md`, REQ, design, review, qa) แยกจาก **Runtime state** (orchestrator: phase execution/review/qa, attempt, session ต่อ task) — runtime state ไม่ถูกเขียนลง module docs โดยไม่จำเป็น
- task ที่ค้างกลางรันตอน orchestrator ปิด/ล่ม (OQ-18, OQ-11 — เจ้าของ jtrp98 2026-10-05):
  - ไม่ถูกนับว่าเสร็จ และเริ่มใหม่ใน session ใหม่ — ไม่นับเป็น fix round
  - restart อัตโนมัติได้ 1 ครั้งต่อ task แล้วขึ้น Waiting on Human (ค่า 1 เป็น config — สมมติฐาน — ยังไม่ยืนยัน)
  - ไฟล์ที่แก้ค้างไม่ถูก revert อัตโนมัติ · packet ของ session ใหม่มีรายการไฟล์ที่ session ก่อนแก้ (จาก write audit)
- Status ใน `plan\index.md` (project state) — orchestrated mode: orchestrator คัดลอกจาก verdict ของ qa-engineer, ค่าได้แค่ `pending`/`verified`/`blocked` (REQ-011, OQ-14) · running/attempt/phase ไม่ลง docs
- ใน orchestrated mode ตัวจำ/ตัวตัดสินลำดับคือ orchestrator ไม่ใช่ LLM session · solo mode: runtime state อยู่ใน session หลัก + artifact เหมือนเดิม (OQ-17)

- **AC-065** — dashboard แสดงต่อ task: phase (execution/review/qa), attempt ที่เท่าไร, session ของ task — และค่า attempt/session ไม่ปรากฏใน module docs
- **AC-066** — ปิด orchestrator ขณะมี task running แล้วเปิดใหม่: task นั้นไม่แสดงเป็นเสร็จ และถูกเริ่มใหม่ใน session ใหม่ (session id ต่างจากเดิม) ที่ packet มีรายการไฟล์ที่ session ก่อนแก้ — ไฟล์เหล่านั้นไม่ถูก revert
- **AC-075** — task เดียวกัน crash ซ้ำหลัง restart อัตโนมัติครบค่าใน config: ขึ้น Waiting on Human, ไม่ restart เองอีก และตัวนับ fix round ของ task ไม่เพิ่มจากการ crash
- **AC-067** — ไม่มีขั้นใดที่ระบบถาม LLM ว่า "task ไหนรันอยู่/เสร็จแล้ว/ถึงรอบไหน" — ตรวจจาก log ของ orchestrator
