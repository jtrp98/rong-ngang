# BE-020 — Minimum context loader: ID → ไฟล์ (DES-020)

## Goal

คำนวณ `readSections` ของทุก packet จาก ID ที่ถูกอ้าง ผ่าน index ของหมวด — session ได้เฉพาะ minimum context และ agent ไม่เลือกไฟล์เอง

## Scope

- ตาราง resolve ตายตัวของ DES-020 (REQ / AC / DES / task id / TP / REV / QA / data-model) · หน่วย = ไฟล์ · ไม่ resolve section ในไฟล์
- แหล่ง id: `## References` ของ task file + `blocker.reference` + defect `findings[].reference` + reproduce `tp` · regex + รูปมีหมวดนำ `qa:`/`review:`/`test-plan:` (DES-020 Rev 11)
- id ชนกัน (task `QA-001` vs finding `QA-001`): ลำดับ resolve ตายตัว 3 ข้อของ DES-020 — ไม่เกิด `context-error` · `contextFiles` บันทึกชนิดที่ resolve
- context ต่อ kind/role ตามตาราง DES-020 (ห้ามเกินโดยไม่มี ID อ้าง)
- id หาไม่เจอ / index ชี้ไฟล์ที่ไม่มี / index parse ไม่ผ่าน → ไม่ dispatch + hold `context-error` พร้อม id + index ที่หา (fail-closed)
- คืน `readSections` (path สัมพัทธ์ module folder) + `contextFiles` ให้ SessionRecord + บรรทัดแรกของ session log (AC-047)
- Write paths: `agent-team/src/core/context-loader.ts`, `agent-team/test/context-loader.test.ts`
- Security-sensitive: no

## Out of Scope

- เลือกไฟล์ด้วย LLM · เดา path เมื่อ index ไม่มีตาราง TP/REV/QA (→ `context-error`) · ประกอบ packet (BE-006)

## Expected Output

- loader ที่ BE-006 ใช้เติม `readSections`

- node:test fixture module split — engineer packet มีเฉพาะ `plan\index.md` + task file + REQ/DES ที่อ้าง (AC-046) · ไม่มีไฟล์ที่ไม่ถูกอ้าง / round เก่า / conversation (AC-033, AC-046)
- id หาไม่เจอ → `context-error` ระบุ id + index (AC-048) · `contextFiles` ครบสำหรับ log (AC-047)
