## DES-014 — โครงสร้างเอกสาร module (split layout)

**Traces:** REQ-005 (AC-011, AC-012), REQ-003, REQ-011 (AC-036, AC-038, AC-039, AC-074, AC-079), REQ-008 (AC-021), REQ-018 (AC-059)

**Rule:** เอกสารของ module หนึ่งแตกเป็น **ไฟล์ย่อย + index เป็นสารบัญ** — หน่วยอ่านเล็กที่สุดคือไฟล์จริงหนึ่งไฟล์ (เจ้าของ 2026-10-05):

```
knowledge\<module>\
├── index.md                 ← สารบัญหลัก (BA) — ลิงก์ index ย่อย + change log + วิธีอ่าน เท่านั้น
├── requirement\             ← index.md (id|ชื่อ|status|AC + แถว scope.md) + scope.md (Overview/Target Users/Release Scope/Constraints/Declined/References) + req-001.md… (1 REQ + AC ต่อไฟล์)
├── design\                  ← index.md (feasibility + ตาราง DES + how-to-read) + data-model.md + des-001.md… + quality-attributes.md + modules.md + risks.md + archive.md
├── plan\                    ← index.md (release scope, waiting-on-human, phase overview, ตาราง Tasks: Task|Name|Owner|Phase|Depends|Status) + <task-id>.md… (1 task ต่อ 1 ไฟล์ ไม่มี Status)
├── test-plan\ review\ qa\   ← โครงเดียวกัน (qa/review แตกต่อ round: round-N.md)
├── open-questions\          ← index.md (ตาราง: id|คำถามย่อ|ผู้ตอบ|สถานะ|ไฟล์) + oq-<id>.md… (1 OQ ต่อ 1 ไฟล์)
└── backlog.md               ← ไฟล์เดียว (append-only) ไม่แตก
```

**กติกาอ่าน:** packet `readSections` เป็น **path list ตรง** (เช่น `design\des-006.md`) — agent อ่าน index ของหมวดที่ packet ชี้ก่อน แล้วอ่านเฉพาะไฟล์ที่ packet ระบุเท่านั้น **ห้าม ls ห้ามอ่านข้ามหมวด** (grep ภายในไฟล์ที่ได้รับอนุญาตทำได้) — index ของหมวดคือแหล่งรายชื่อไฟล์เดียว

**Status อยู่ที่ index เท่านั้น:** task status อยู่คอลัมน์เดียวใน `plan\index.md` ค่า `pending`/`verified`/`blocked` เท่านั้น · ผู้เขียน (OQ-14): PM = แถวใหม่ `pending` · orchestrated = orchestrator คัดจาก verdict ของ qa-engineer (DES-007) · solo = qa-engineer · audit ตรวจคอลัมน์ได้จริง (DES-021 ข้อ 5) · REQ status อยู่ `requirement\index.md`
