**Rule:** ทุก stage สื่อสารกับ agent ผ่านสอง artifact ที่มี schema ตรงตัว: **packet** (input — packetVersion 2, โครงใน §Data Model) และ **handoff-v2.json** (output สุดท้าย — Rev 10; v1 → `archive.md`) **`readSections` เป็น `string[]` ของ path ตรง** (เช่น `["design\\index.md", "design\\des-006.md"]`) — agent อ่าน index ของหมวดที่ packet ชี้ก่อน แล้วอ่านเฉพาะไฟล์ที่ packet ระบุเท่านั้น ห้าม ls ห้ามอ่านข้ามหมวด (grep ภายในไฟล์ที่ได้รับอนุญาตทำได้) — แทนกติกา "อ่านเป็น section" เดิม (DES-014, 2026-10-05) handoff บังคับโครงด้วย structured-output flag ของ CLI (`--json-schema` claude/agy, `--output-schema` codex — DES-002) ทำให้การ parse เป็น deterministic ไม่อาศัยการอ่านข้อความอิสระ; โครงข่าย handoff ออกแบบให้ครอบของเดิมที่ role prompt กำหนด ("Handoffs are short": result, evidence, blockers, next role — `sta2\CLAUDE.md:36,92`) โดยเพิ่ม field ที่ driver ต้องใช้: `outputState` (แทน `status` ของ v1), `questionsForHuman` (gate + question ตรงตัว + owner), `changedDocs/changedCode`, `decision` (เฉพาะ BA งานใหม่) และ packet มี field บริบทการเลือกงาน `selectedTarget` (name + path — path นี้คือ codeRoots ของ stage นี้ มาจาก target ที่เลือกตาม sta-config.json — DES-015, DES-011) และ **`gitPolicy`** (R1: โครงคงเดิม ค่า `commitAllowed: false` ทุก root — REQ-009 ไม่อยู่ R1, DES-015 · สิทธิ์ commit ต่อ root — `rootKind`, `path`, `commitAllowed`, `warning` — คัดจาก `run.json.gitPolicy` ที่ freeze ตอนเริ่ม run ทุก stage ของ run เดียวกันได้ค่าเดียวกัน; agent ใช้ค่านี้เท่านั้น ห้ามอ่าน sta-config เพื่อตัดสินเอง — DES-015/016, REQ-009) นี่คือส่วนขยาย (additive) ต่อ role prompt — packet ประกาศชัดว่า handoff เป็นส่วน output contract ของระบบ ไม่ใช่การแทนที่กติกา handoff ใน prompt
