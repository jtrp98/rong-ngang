## Risks & Dependencies

**Dependencies:** Node ≥ 20 + npm บน Windows — ตรวจ 2026-10-04: `node --version` = **v24.21.0** (ผ่านเงื่อนไข ≥ 20), `npm --version` = 11.19.0 มีอยู่บนเครื่อง; รัน .ts ด้วย tsx (devDep) ไม่ต้องมี build step · CLI ทั้งสามติดตั้ง + login แล้ว (ยืนยัน 2026-10-04) · role prompt + templates จาก pack ที่ `code\` (packRoot — pack เป็น asset ของสินค้า ย้ายเข้า `code\` 2026-10-05; fork จาก sta2 — สร้างโดย setup role ตาม task ใน plan; ต้นฉบับ sta2 อ่านอย่างเดียว) · `code\sta-config.json` — machine-local registry ผูก knowledge/target (DES-015) · npm dependency เดียว: **`yaml`** (parse config yaml ที่คนเขียน) — เลือกเพราะ (1) mature/ใช้แพร่หลายและเอกสารครบ, (2) `YAMLParseError` ของ lib รายงาน line/column ของ parse error ได้เช่นกัน ตรงกับข้อบังคับ fail-closed "รายงาน path ของไฟล์ที่เพี้ยน" (DES-001), (3) config เป็นไฟล์เล็กอ่านครั้งเดียวต่อ run — ไม่ต้องการ throughput/feature อื่น; tier engine ของ orchestrator เดิม (`software-team-agents\orchestrator\src\runtime\tierRouting.ts` ฯลฯ) เป็น TypeScript อยู่แล้ว port ได้เกือบ 1:1 — เหตุผลหลักที่กลับมา Node (งานทั้งหมดเป็น glue code)

**Risks (เรียงตามผลกระทบ):**

1. **codex effort key `model_reasoning_effort` ยังไม่ยืนยันกับ 0.160.0 โดยตรง** (`inferred (doc)` — DES-002) — ผลถ้าผิด: tier ฝั่ง codex ไม่มีผล เจอตอน smoke test; แก้ที่ camps.yaml
2. **CLI output/schema เปลี่ยนตามเวอร์ชัน** — จับด้วย smoke test ต่อ camp + บันทึกเวอร์ชันต่อ stage; อัปเดต camps.yaml เมื่อ CLI อัปเดต
3. **Windows command-line length** — บรีฟ/role prompt ยาว → ทุก camp ใช้ packet-file/stdin แล้ว (DES-002) เหลือเสี่ยงแค่ positional prompt สั้น ๆ ของ codex/agy
4. **write audit ระดับไฟล์** จับไม่ได้ที่ระดับ cell (Status cells) และจับ regenerate-โดย-เจ้าของไฟล์ไม่ได้ — บังคับด้วยบรีฟ ประกาศข้อจำกัดแล้ว (DES-006, DES-011); `git init` ที่ rong-ngang ตัดสินแล้ว (OQ-D4 ปิด 2026-10-04): init โดย setup role ตอนขั้นตั้งโปรเจกต์ แล้ว audit เป็น git-primary/manifest-fallback — ในโครง split คอลัมน์ Status ของ `plan\index.md` ตรวจได้แล้ว (ไฟล์เล็กแยก — DES-006/014) ส่วน cell ของไฟล์ใหญ่อื่นยังเป็นข้อจำกัด
5. **ไม่มี auth บน local UI** — ลดด้วย loopback bind + Host header check; ห้าม expose ผ่าน network
6. **prompt injection ผ่านงานใหม่/เนื้อหาเอกสาร** — ลดด้วย packet เป็นข้อมูล + handoff schema + write scope + gate; เหลือความเสี่ยงคงเหลือยอมรับไว้สำหรับ release local ผู้ใช้เดียว
7. **role prompt เปลี่ยนที่ packRoot โดยไม่แจ้ง** (fork — 2026-10-05 ไม่ใช่ sta2 อีกต่อไป) — hash ต่อ dispatch ทำให้ตรวจย้อนได้; ไม่ pin เวอร์ชัน (ตั้งใจให้ทั้งสองโหมดใช้ชุดเดียวกันเสมอ — REQ-003)
8. **auth ของ CLI หมดอายุกลาง run** — spawn fail → retry → failed + แจ้ง; คน login ใหม่แล้วกด resume
9. **`agy --sandbox` semantics ยังไม่ละเอียดจาก help** (`inferred`) — ตรวจพฤติกรรมจริงตอน smoke test ก่อนใช้งานจริง
10. **effort บน haiku (T6 claude) ไม่มีผล** — รู้แล้วจากของเดิม (`tier-and-effort-run.md:97-98`); tiers.yaml ตั้ง effort: null ให้ T6 claude แล้ว อย่าคาดหวังความต่างจาก effort
11. **index drift** — เพิ่ม/ลบ/เปลี่ยน id ในไฟล์ unit แล้วลืมอัปเดต index ของหมวด (หรือกลับกัน) → agent หาไฟล์ไม่เจอ/อ่านข้าม (DES-014) — mitigation: validator ของ DES-014 ตรวจ index กับไฟล์ตรงกันสองทาง (BE-001) และ run หยุดรอคนเมื่อไม่ตรง (fail-closed)
12. **sta-config เป็น machine-local** — คนละเครื่อง path ต่างกัน และ gitignored ไม่ commit (DES-015) → เครื่องใหม่/สมาชิกใหม่ต้องรัน setup prompt ต่อเครื่องก่อนใช้; config หาย/path ไม่มีจริง → ปฏิเสธ run (fail-closed) — mitigation: setup prompt ตรวจ/สร้างโครงตาม DES-014 และเขียนรายการให้ (phase 1)
13. **สวิตช์ `gituse` default เปิด (REQ-009, 2026-10-05)** — AI commit ได้ทุก root ที่ไม่ตั้งค่า; codex/agy กันก่อนไม่ได้ (บรีฟ + ref audit หลัง stage เท่านั้น), solo ไม่มี audit เลย, push ด้วย URL ตรงจับไม่ได้, การสลับไม่มีประวัติ (OQ-9) — mitigation: freeze ต่อ run, `--disallowedTools` ฝั่ง claude, ref audit (DES-016) · pack `code\.claude\settings.json` deny `git add`/`git commit` แบบ static ต้องแก้ ไม่งั้นสวิตช์เปิดไม่มีผลใน claude/zcode (รอเจ้าของยืนยัน)
14. **target = orchestrator home ใน dogfood (สังเกต 2026-10-05)** — `code\sta-config.json:8` target path = `code/agent-team` ซึ่งอยู่ใน universal deny `code/agent-team/**` ของ DES-006 → engineer เขียน codeRoots ไม่ได้ใน orchestrated run บนเครื่องนี้ (ยังไม่แก้ — ต้องตัดสินแยกจาก REQ-009)
