## Quality Attributes

ตอบตาม `policies\architecture.md:14-24` §2:

- **Performance and load:** ผู้ใช้คนเดียว local — load จริงอยู่ที่ latency ของ CLI (นาทีต่อ session) · Rev 10: session พร้อมกัน ≤ `maxParallelSessions` (ตั้งต้น 3 — สมมติฐาน) · จุดที่ degrade ก่อน: (1) quota/rate limit ของ subscription camp เมื่อ 3 session ยิงพร้อมกัน (2) quiesce ก่อน QA round หยุดเริ่ม execution บน codeRoot เดียวกัน (DES-019) (3) snapshot hash ทุก root ต่อ session start/end — โตตามจำนวนไฟล์ไม่ ignore (DES-021) · engineer ที่ไม่ระบุ Write paths รันทีละตัวต่อ codeRoot · timeout ต่อ session 1800s → R16 · UI อ่าน state ไฟล์อย่างเดียว
- **Failure modes:** ตัดสินไว้แล้วในตาราง router (DES-018): spawn ไม่สำเร็จ → `retryOnCrash`; session crash/timeout/orchestrator ล่ม → session ใหม่ 1 ครั้ง (kill orphan ก่อน — DES-007) แล้ว hold `crash-limit`; handoff เสีย → hold `invalid-handoff` ไม่เดา; audit ไม่ชัด → hold ทุก suspect (fail-closed); fail ครั้งที่ 3 → gate 4; gate ค้าง → หยุดเฉพาะ scope (AC-072); config/plan เสีย → ไม่ dispatch พร้อมชี้ไฟล์ · ไม่มี auto-revert
- **Observability:** SessionRecord ต่อ session (camp/model/effort/basis — AC-005, `contextFiles` — AC-047, writeAudit, pid), `router.log` (ruleId ต่อ decision — AC-069), log ต่อ session, GateRecord append-only, TaskRuntime บน dashboard (DES-022), rolePromptHash, configSnapshot + scheduler ที่ freeze ต่อ run
- **Deployment:** ติดตั้ง = `npm install` ที่ `code\agent-team\` (dependency เดียว: `yaml`) + แก้ registry.yaml (path) + ตรวจชื่อ owner ใน gates.yaml (ตั้งต้น `jtrp98` — OQ-D5); รันด้วย `tsx` (ไม่มี build step — ตัดสินใจแล้ว 2026-10-04) — ตรวจ 2026-10-04: Node **v24.21.0** (≥ 20 ตามที่กำหนด), npm 11.19.0 มีอยู่บนเครื่องแล้ว; ไม่มี service/daemon — ปิดแล้ว pipeline หยุด, resume ได้จาก state · Rev 10 ต้องมี `git` binary (Git Bash) สำหรับ `git diff --no-index` (DES-021) — ไม่มี → diff เป็นรายชื่อไฟล์
- **Compatibility and maintainability:** additive ต่อ sta2 ทุกด้าน (ไม่แตะไฟล์ sta2 นอกจากอ่าน); จุดเปลี่ยนที่ควบคุม: camp flags อยู่ camps.yaml, tier binding อยู่ tiers.yaml, role prompt อยู่ที่เดียว — การอัปเดต CLI เวอร์ชันใหม่แตะ camps.yaml เป็นหลัก · Rev 10 breaking ภายใน design (registry `scheduler`, run.json, packet v2, handoff-v2) — gate 2 · plan legacy ยังอ่านได้ (serial + ธง migrate)
- **Operational cost / vendor lock-in / tech debt:** ต้นทุน = subscription ของ 3 camp เดิม (ไม่เพิ่ม API key) — parallel เพิ่มการใช้ quota ต่อชั่วโมง ไม่เพิ่มต่อ task; lock-in ถูกจำกัดที่ adapter (flags ต่างกันจริง — ยอมรับ); tech debt ที่ยอมรับพร้อมทิศทาง: (1) write audit แบบ detective + จับการเขียนลง claim ของอีก session ไม่ได้ (ทิศทาง: path rule ต่อ camp เมื่อยืนยันได้ / sandbox ต่อ session), (2) parallel ของ engineer ขึ้นกับ PM ระบุ Write paths (ทิศทาง: claim อัตโนมัติจาก DES ที่ task อ้าง — ยังไม่ออกแบบ), (3) role prompt พึ่ง path ใน pack (ทิศทาง: ทำสัญญา version ถ้าโครงเปลี่ยน), (4) ตัวนับ runtime หายถ้า state หาย (ทิศทาง: derive จาก review/qa round files)
