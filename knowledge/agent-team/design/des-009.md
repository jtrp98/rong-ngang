## DES-009 — Web UI และ local API server

**Traces:** REQ-001 (AC-001, AC-002, AC-003), REQ-006 (AC-014), REQ-007 (AC-017, AC-018), REQ-009 (AC-029, AC-031, AC-032)

**Rule:** Node http server (build-in `node:http` — ไม่มี framework ใหญ่ ไม่มี bundler) รันใน process เดียวกับ driver และ bind loopback `127.0.0.1:<port>` เท่านั้น (registry.yaml `ui.host` = 127.0.0.1, `ui.port` = 7800) หน้าเว็บเป็น static single page (`ui/index.html` serve จากโค้ด server เอง, vanilla JS — ไม่มี bundler/framework) มี 2 กรณีตาม REQ-001: (1) ตัวเลือกงานเดิมเป็น **2 ระดับ: knowledge → target** (อ่านรายการจาก `sta-config.json` — DES-015) ก่อนเลือก module ใต้ knowledge root ที่เลือก — เลือกแล้วเห็นสถานะ (stage ถัดไป, task ค้าง, `## Waiting on Human`) + ปุ่มเริ่มงาน — ถ้ามี gate ค้าง ปุ่มพาไปหน้าตอบ gate แทนการเริ่ม (OQ-5); run ที่เริ่มผูกกับ target ที่เลือก — codeRoots ของ run = path ของ target (DES-011); (2) ช่องพิมพ์งานใหม่ + ปุ่มส่ง (DES-010) + แสดงผลตัดสินของ BA (AC-018)

**Endpoints:**

| Method/Path | หน้าที่ |
|---|---|
| `GET /api/modules` | รายชื่อ module ใต้ knowledge root ของ target ที่เลือก (query `knowledge=<name>&target=<name>` — DES-015) + สถานะสรุปต่อ module (run state + เอกสารจริง) |
| `GET /api/modules/<name>` | สถานะละเอียด: stage ถัดไป, task ค้าง, gate ที่ open (question ตรงตัว + owner — AC-014), stage ล่าสุด + camp/model/effort/basis (AC-005) + `gitPolicy` ที่ freeze ของ run ล่าสุด (DES-015) |
| `POST /api/modules/<name>/start` | เริ่ม/resume run — body เลือก `knowledge` + `target` ตาม sta-config.json (DES-015); ถ้ามี gate open คืน 409 พร้อม gateId ให้ UI พาไปหน้าตอบ |
| `POST /api/tasks/new` | body `{text}` — ข้อความงานใหม่ดิบ (DES-010) |
| `GET /api/gates/<gateId>` | รายละเอียด gate |
| `POST /api/gates/<gateId>/answer` | body `{answer, answeredBy, note?}` — ปิด gate (DES-008) |
| `GET /api/runs/<runId>/events` | SSE — ส่ง event ต่อ stage transition/log tail แบบสด |
| `GET /api/config` | อ่าน config อย่างเดียว (routing/tiers/gates + รายการ knowledge/target จาก sta-config.json — DES-015) เพื่อโชว์ใน UI · ต่อ knowledge/target มี `gituse: boolean \| null` (ค่าที่ตั้ง; null = ไม่ตั้ง) + `gituseEffective: boolean` + `gituseBasis: "target" \| "knowledge" \| "default"` + `repo: boolean` (read-only `rev-parse`) + `auditMode: "git" \| "manifest"` + `warning: string \| null` (เปิดแต่ไม่ใช่ repo — AC-031) — 2026-10-05 |

**สวิตช์ `gituse` บน UI (2026-10-05 — REQ-009, DES-015):** แสดงอย่างเดียว ไม่มีปุ่มสลับ (สลับด้วย `/gituse` — DES-017) · `GET /api/config` = ค่าปัจจุบันของ config; run ที่วิ่งอยู่ใช้ `gitPolicy` ที่ freeze (AC-029) · `POST .../start` ไม่ปฏิเสธเพราะ git (non-repo = เตือน + ข้าม commit) · ไม่มี remote/ไม่ตรวจ origin (AC-032)

**Permissions/States/Errors:** ไม่มี auth ใน release นี้ โดยมีเงื่อนไข: bind loopback เท่านั้น + ประกาศชัดว่าทุก request บนเครื่องนี้เรียกได้ (มิได้ประเมินว่ามันคือ "เจ้าของ" — การอนุมัติบันทึก answeredBy ที่ผู้ตอบพิมพ์เองจึงยัง honest ตาม AC-016); `POST /api/tasks/new` จำกัดความยาว (default 20,000 ตัวอักษร) · **Compatibility:** additive · **Data/schema · Migration:** ไม่มี · **Security (trust boundary — security.md §3):** boundary เดียวคือ loopback vs นอกเครื่อง — ไม่ bind 0.0.0.0, ไม่มี port-forward ที่ระบบทำเอง; privilege model = ผู้ใช้คนเดียวบนเครื่อง local; abuse cases พิจารณา: (1) ข้อความงานใหม่เป็น untrusted input — ไปเป็นข้อมูลใน packet เท่านั้น ไม่ถูกประกอบลง command line (DES-002 ใช้ packet file + argv array), (2) DNS rebinding ต่อ local API — ตรวจ `Host` header ต้องเป็น `127.0.0.1:<port>` เท่านั้น, (3) หน้าเว็บเรียก resource ภายนอก — ไม่มี: static page ไม่โหลด CDN · **Fallback:** UI ล่มไม่กระทบ run ที่กำลังวิ่ง — driver ทำงานต่อและ gate แจ้งทาง terminal แทน (REQ-006 ระบุ dashboard/**terminal**)

**Evidence:** `requirement.md:23-33` (REQ-001 + OQ-5 default) · `requirement.md:85-97` (แจ้งผ่าน dashboard/terminal) · แนว Web UI local ของเดิมอ้าง :9889 (requirement.md:142 — ใช้แนวคิด ไม่ใช้ port)
