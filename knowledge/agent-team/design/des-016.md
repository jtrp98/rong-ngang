## DES-016 — สิทธิ์ git commit ต่อ root (`gituse`): การบังคับ

> Budget ≤ 8 KB · เขียนโดย `system-analyst` · 1 contract · resolve/validate/freeze ของสวิตช์ = DES-015 · คำสั่งสลับ `/gituse` = DES-017

**Traces:** REQ-009 (AC-026, AC-027, AC-029, AC-030, AC-031), REQ-008 (solo), DES-006, DES-012, DES-013, DES-015

**Rule:** สิทธิ์ commit = permission ต่อ root จาก `gitPolicy` ที่ freeze ตอนเริ่ม run (DES-015) · orchestrator **ไม่ commit เอง** ไม่กำหนดจังหวะ/ขอบเขต/ข้อความ commit (AC-030)

| กลุ่ม git | คำสั่ง | ผล |
|---|---|---|
| อ่าน | status, diff, log, show, rev-parse, symbolic-ref, for-each-ref | อนุญาตเสมอ (AC-026) |
| commit | `git add -- <path>`, `git commit` | เฉพาะ root ที่ `commitAllowed: true` · path ต้องอยู่ใต้ root นั้น + ใน `writeScope.allow` |
| ห้ามเสมอ | push, branch, checkout, switch, merge, rebase, reset, tag, stash, cherry-pick, revert, restore, clean, rm, mv, init, clone, fetch, pull, `commit --amend` | ปฏิเสธทุก root ทุกค่า (AC-030) |

- **ชั้น 1 — packet/brief (ทุก camp):** `gitPolicy` ใน packet (DES-012) + ประโยคบังคับ: commit เฉพาะ root ที่ `commitAllowed`; `git add -- <path ที่ stage นี้เปลี่ยน>` ห้าม `git add -A`/`.`; root ที่มี `warning` ให้ข้าม commit; ห้ามแก้ sta-config
- **ชั้น 2 — CLI-native (claude เท่านั้น):** `--disallowedTools` กลุ่มห้ามเสมอทุก stage (Bash + PowerShell) · ทุก root ของ stage ปิด → เพิ่ม `git add`/`git commit` · มี root เปิด → `--allowedTools` `Bash(git add:*)`, `Bash(git commit:*)` (แยกต่อ root ไม่ได้ → ชั้น 3 จับ) — รูป rule `inferred` · codex/agy ไม่มี rule ระดับคำสั่ง → ชั้น 1 + 3
- **ชั้น 3 — ref audit หลัง stage (detective, ต่อ `repoTop` ที่ `repo: true`):** ก่อน dispatch เก็บ `symbolic-ref -q HEAD`, `rev-parse HEAD`, `for-each-ref refs/heads refs/remotes refs/tags` · หลัง stage → violation เมื่อ (ก) symbolic HEAD เปลี่ยน (ข) ref อื่นใน refs/heads เกิด/หาย/ย้าย (ค) refs/remotes หรือ refs/tags เปลี่ยน (ง) branch ปัจจุบันย้ายแบบไม่ fast-forward (`merge-base --is-ancestor` ไม่ผ่าน) (จ) commit ใหม่มี parent > 1 (ฉ) commit ใหม่แตะ path ใต้ root ที่ `commitAllowed: false` หรือ HEAD ย้ายใน repo ที่ไม่มี root ใดเปิด (AC-027) · ไฟล์ใน commit ใหม่ (`diff --name-only <before>..<after>`) นับเป็น changed ของ write audit (DES-006) · violation → stage failed, run `stopped` รอคน — ไม่ revert อัตโนมัติ
- **non-git root (AC-031):** `commitAllowed: false` + `warning` ตั้งแต่ freeze → AI ข้าม commit, run ไม่ล้ม
- **solo mode (DES-013):** session (driver) resolve ตามกฎ DES-015 ตอนเริ่ม "run" = การขับ pipeline หนึ่งครั้งตามคำสั่งผู้ใช้จนหยุดที่ gate/จบ — ไม่อ่านซ้ำกลางทาง (AC-029) · เปิดแต่ไม่ใช่ repo → เตือน + ข้าม · บังคับด้วย prompt (`CLAUDE.md` ที่ packRoot: hard rule "No state-changing git" ยกเว้น `git add`/`git commit` เมื่อ effective `gituse` = true) + `.claude\settings.json` deny กลุ่มห้ามเสมอ · ไม่มีชั้น 3 (ข้อจำกัดเดิมของ solo)

**Inputs/Outputs:** Input: `gitPolicy` (DES-015), snapshot ref ก่อน/หลัง stage · Output: `writeAudit.violations[]` kind `git-ref`/`git-commit-off` + `gitRefs` ใน StageRecord (data-model)

**Permissions/States/Errors:** ตามตาราง · git หายกลาง run → ref audit ของ stage นั้น `partial` + เหตุ (ไม่ถือว่าผ่านเงียบ)

**Compatibility:** additive ต่อโค้ด (ยังไม่ build) แต่**เปลี่ยนกติกา pack:** hard rule "No state-changing git" มีข้อยกเว้นเมื่อสวิตช์เปิด, default เปิด (เจ้าของยืนยัน OQ-8 (4)) · **`code\.claude\settings.json:5-6,24-25` deny `git add`/`git commit` แบบ static** → ไม่แก้ = สวิตช์เปิดไม่มีผลใน claude/zcode (และ orchestrated claude ที่ cwd ใต้ `code\` — `inferred`) · ข้อเสนอ: ถอด `git add`/`git commit` (Bash + PowerShell) ออก คงรายการอื่น; root ที่ปิดบังคับด้วยชั้น 1–3 (solo = prompt) — **รอเจ้าของยืนยัน** · **Data/schema · Migration:** `gitPolicy`, `writeAudit.mode/partial/gitRefs`, `violations[]` มีโครง (data-model) — ยังไม่มี run จริง ไม่มี migration

**Security:** boundary = AI agent (ไม่ไว้ใจต่อ git state) ↔ repo ของผู้ใช้ · privilege: commit-only ต่อ root ที่เปิด, ไม่มี network op · abuse: (1) `git add -A` กวาดงานค้างของผู้ใช้ → บรีฟห้าม; audit จับเมื่อ path นอก allow (ใน allow จับไม่ได้ — ประกาศ) (2) role แก้ `gituse` ให้ตัวเอง → run นั้นไม่ได้ผล (freeze) แต่ run ถัดไปได้ และไม่มีประวัติ (OQ-9) — คงเหลือ ส่ง `security` (3) push ด้วย URL ตรงที่ไม่อัปเดต refs/remotes → ชั้น 3 จับไม่ได้; claude กันด้วยชั้น 2, codex/agy เหลือบรีฟ (4) amend/reset/rebase → ชั้น 3 (ง) · ผลเสียสูงสุด = commit ในเครื่องที่ย้อนได้ (ไม่ประเมินเป็น Critical)

**Fallback:** ไม่มี git/ไม่ใช่ repo → `commitAllowed: false` + warning, audit manifest (DES-006) · ref audit ล้ม → `partial`

**Quality attributes:** observability = warning/violation บน dashboard + terminal + run.json · performance = git read ~4 คำสั่ง/repo/stage · deployment/tech debt — ไม่มีผล
