## DES-002 — Camp adapters: headless spawn ต่อ camp

**Traces:** REQ-002 (AC-004, AC-005)

**Rule:** adapter ต่อ camp แปลง (role prompt, brief/tier → model/effort, write scope, output contract) เป็น command line ของ CLI นั้น — spawn ผ่าน `child_process.spawn` (Node) ด้วย argv array ตรง (ไม่ผ่าน shell) — บรีฟเดียวกันสั่งได้ทั้ง 3 camp โดยไม่แก้บรีฟ (AC-004) เพราะบรีฟอยู่ใน packet ที่ camp-agnostic เสมอ (DES-012)

**Inputs/Outputs — command line ต่อ camp (ชื่อ flag จาก `--help` จริง 2026-10-04):**

- claude: `claude -p --output-format json --permission-prompts none --permission-mode dontAsk --model <model> --effort <effort> --json-schema <handoff-v1.json> --append-system-prompt-file <rolePrompt.txt> --allowedTools <จาก frontmatter tools: ของ role> --disallowedTools ... --add-dir <docsRoot> --add-dir <codeRoots>` โดยบรีฟ (ข้อความสั้น: "ทำงานตาม dispatch packet ที่ <packetPath>") ส่งทาง stdin, cwd = packRoot (`code\` — DES-013 เปิด session ที่ `code\`)
- codex: `codex exec --json --skip-git-repo-check --sandbox workspace-write --cd <packRoot = code\> -m <model> -c model_reasoning_effort="<effort>" --output-schema <handoff-v1.json> -o <lastMessagePath> "<อ่านและทำตาม dispatch packet ที่ <packetPath>>"` — role prompt + brief ทั้งหมดอยู่ใน packet ไฟล์
- agy: `agy -p --output-format json --json-schema <handoff-v1.json> --model <model> --effort <effort> --add-dir <docsRoot> --add-dir <codeRoots> --log-file <logsPath> "<อ่านและทำตาม dispatch packet ที่ <packetPath>>"`

Output ที่ driver อ่านกลับ: claude → stdout JSON (โหมด `--output-format json` ให้ผลลัพธ์ชิ้นเดียว); codex → JSONL events (`--json`) + ไฟล์ last message (`-o`); agy → stdout JSON ตรวจความสำเร็จด้วย exit code 0 + handoff JSON ผ่าน schema สำเร็จ

**Permissions/States/Errors:** ห้ามใช้ `--dangerously-skip-permissions` (claude/agy) หรือ `--dangerously-bypass-approvals-and-sandbox` (codex) เด็ดขาด — ชื่อ flag มีจริงใน help แต่ไม่อยู่ในโปรไฟล์ ต่อ stage มี timeout `defaults.timeoutSec` เกินเวลา → kill child process, outcome=timeout, retry ตาม `retryOnCrash` (default 1) ครบแล้วยังพัง → run failed รายงานผู้ใช้ (fail visibly ตาม architecture §2) · **Fallback:** ถ้า flag `--json-schema`/`--output-schema` ล้มเหลวบน CLI เวอร์ชันใหม่ → ตกไป parse fenced JSON block ใน output ธรรมดา; ถ้า parse ไม่ผ่าน → stage failed (ไม่เดา)

**Compatibility:** additive — แต่ schema ของ CLI output เปลี่ยนได้เมื่อ CLI อัปเดต → บันทึก `version` ของ CLI ใน StageRecord ตอน spawn และ smoke test ทุก camp ก่อนใช้ (DES-006 risks) · **Data/schema · Migration:** camps.yaml เป็นคนเขียน/คนแก้ · **Security:** ไม่ผ่าน secret เข้า argv เด็ดขาด — CLI ใช้ auth ที่มัน login ไว้เอง (claude/codex/agy ไม่ต้อง API key ใน config ตาม constraint ของ REQ) · **Evidence:** claude 2.1.287 `--help`: `-p, --print`, `--output-format (text|json|stream-json)`, `--model`, `--effort`, `--json-schema`, `--permission-prompts` (`none` = "anything that would prompt is denied automatically"), `--permission-mode` (มี `dontAsk`), `--append-system-prompt[-file]`, `--allowedTools/--disallowedTools`, `--add-dir` · codex 0.160.0 `exec --help`: `-m, --model`, `-c, --config`, `-s, --sandbox` (possible values: `read-only, workspace-write, danger-full-access`), `--cd`, `--skip-git-repo-check`, `--json`, `--output-schema`, `-o, --output-last-message` · agy 1.2.16 `--help`: `-p/--print`, `--output-format (text|json|stream-json)`, `--json-schema`, `--model`, `--effort (low|medium|high|xhigh|max)`, `--add-dir`, `--sandbox`, `--log-file` — ส่วน `-c model_reasoning_effort` ของ codex อ้างจาก `docs\tier-and-effort-run.md:100` (adapter เดิมใช้จริง) + `-c` ยืนยันใน help; ค่า key ยังไม่ยืนยันกับ codex 0.160.0 โดยตรง → mark `inferred (doc)`
