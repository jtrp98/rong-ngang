## DES-001 — Pipeline driver และ DAG scheduler (session lifecycle)

**Traces:** REQ-001 (AC-003), REQ-002, REQ-007 (AC-019), REQ-011 (AC-036, AC-037, AC-039, AC-074, AC-079), REQ-015 (AC-080), REQ-012 (AC-040, AC-041, AC-042), REQ-013 (AC-043, AC-044, AC-045), REQ-020 (AC-067) · router DES-018 · audit DES-021

**Rule:** driver ตัวเดียวที่ spawn agent ("No agent invokes the next" คงเดิม) · ลำดับงานต่อ module มาจาก 3 กรณี ตัดสินจาก header ตาราง Tasks ของ `plan\index.md` (DES-014):
1. **ไม่มี plan / มี change chain** → `change` session แบบ serial ต่อ module: business-analyst → system-analyst → project-manager → [test-planner เมื่อ trigger] (right-size ตาราง `CLAUDE.md` ที่ packRoot เดิม)
2. **plan v2** (header = `Task | Name | Owner | Phase | Depends | Status`) → **DAG scheduler** ข้างล่าง
3. **plan legacy** (ไม่มีคอลัมน์ Depends) → อ่าน Task + Status ได้, dispatch **ทีละ session ต่อ module** เรียง Phase แล้วลำดับแถว, ขึ้นธง `needsMigration` (AC-074 — OQ-15) · ไม่แปลง/ไม่เขียนไฟล์ให้

**DAG scheduler (plan v2):**
- `runnable(T)` ⇔ Status(T) = `pending` ∧ ไม่มี hold ∧ ไม่ active ∧ ทุก d ใน Depends(T) `satisfied` · `satisfied(d)` ⇔ Status(d) = `verified` (BE "เสร็จจริง" — OQ-10, AC-044) · owner ที่ไม่ผ่าน QA (default ของ design — เจ้าของ jtrp98 ยืนยันให้ใช้ 2026-10-05): uxui-designer = gate 3 ของ task นั้น answered · test-planner = `test-plan\index.md` มีแถว TP ของ Phase นั้น · anchor (Owner qa-engineer) = phase `cleared` (DES-019)
- Depends cell: `—`/ว่าง = ไม่มี · หลายค่าคั่น `,` · id ไม่มี/วงวน → R9 (DES-018) · อ่าน `plan\index.md` ใหม่ทุก tick → แก้ Depends อย่างเดียวเปลี่ยน runnable ได้ (AC-037)
- **Tick** = ทุก event (session จบ, gate answered, ไฟล์ plan เปลี่ยน — `fs.watch` + re-read, human action) · parse ไม่ผ่าน (PM แก้ค้าง) → tick นั้นไม่ dispatch ใหม่; ไม่ผ่านต่อเนื่องหลัง PM session จบ → hold module `plan-error`
- **เพดาน:** session ที่ active ทุก kind ทุก module ≤ `scheduler.maxParallelSessions` (ค่าเดียว ตั้งต้น 3 — สมมติฐาน — ยังไม่ยืนยัน, AC-045) · เกิน → คิว · ลำดับคิว: (1) fix/restart session ของ task เดิม (2) Phase น้อยก่อน (3) ลำดับแถวในตาราง — deterministic
- ก่อน dispatch ต้องผ่าน: claim ไม่ชนกับ session ที่ active (DES-021) · ไม่อยู่ใน quiesce ของ QA (DES-019) · gate ที่ scope ครอบ task ไม่ open (DES-008)
- **Multi-task session (OQ-12):** PM ใส่ `- Session group: <id>` ใน `## Scope` ของ task file · orchestrator ตรวจเชิงกลไก: Owner เดียวกัน, Phase เดียวกัน, ไม่มี Depends ระหว่างสมาชิก, ทุกตัว runnable ใน tick เดียวกัน → packet เดียว `taskIds[]` · ไม่ผ่าน → แยกทีละ task + หมายเหตุบน dashboard · default = ไม่รวม (AC-041)

**Session policy (REQ-012 — 1 packet = 1 scope, AC-042):**

| role | 1 session = |
|---|---|
| BA / SA / PM | 1 change หรือ 1 planning/replanning op (`change`) |
| test-planner | 1 phase/test-strategy scope |
| BE / FE / setup / uxui | 1 task (หรือ 1 session group) |
| reviewer | 1 wave (DES-019) |
| qa-engineer | 1 QA round หรือ 1 Feature QA ของ phase |
| security | 1 phase ที่มี 🔒 — stage ท้าย phase ไม่ใช่ task (OQ-20, DES-019) |
| devops | 1 release/deploy |

ทุก dispatch = process ใหม่ + `sessionId` ใหม่ (`s-<runSeq>-<4 hex>`) ไม่ reuse ข้าม task/รอบ (AC-040; รอบแก้ = session ใหม่ — OQ-18) · ไม่มีขั้นใดถาม LLM ว่างานอยู่ไหน (AC-067) — สถานะมาจาก TaskRuntime (DES-007) + เอกสาร

**Inputs/Outputs:** in: `plan\index.md`, task file (`## Scope` lines), TaskRuntime, registry `scheduler` · out: dispatch list → camp adapter (DES-002) · run status: `queued → running ⇄ idle (ไม่มีอะไร runnable/active) → waiting-on-human (gate scope module หรือทุก task hold) | stopped | completed (task ใน Release Scope verified + phase cleared)` — เขียน run.json atomic ทุก transition
