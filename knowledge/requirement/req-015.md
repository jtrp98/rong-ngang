# REQ-015 — Reviewer: clean session ต่อ execution wave + ผลแบบ structured

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น

## กติกาทางธุรกิจ

- reviewer ทำงานใน **clean session** — ไม่เห็น reasoning/conversation ของ implementer
- อ่าน: task, REQ/DES ที่เกี่ยว, changed files, diff, tests · ตรวจ: correctness, design compliance, maintainability, security, test coverage, scope violation, regression · **ไม่แก้ implementation**
- 1 clean reviewer session ต่อ **small execution wave** · task ใหญ่ / security-sensitive / ไม่เกี่ยวกัน → แยก session (OQ-12):
  - wave = task ใน phase เดียวกันของ `plan\index.md` ที่รอ review พร้อมกัน ณ ตอนเปิด review session — ตัดสินด้วย code
  - ค่า config ตั้งต้น: wave ≤ 4 task และ diff รวม ≤ 800 บรรทัด · task "ใหญ่" = diff > 400 บรรทัด หรือ > 10 ไฟล์ (ตัวเลขทั้งหมด — สมมติฐาน — ยังไม่ยืนยัน)
  - security-sensitive = PM ตั้ง flag ใน plan
- review/security ไม่ใช่ task ใน plan (OQ-20): orchestrator เปิด review session เองตาม wave · security session เปิดท้าย phase ที่มี task 🔒 เท่านั้น (🔒 = flag security-sensitive ข้างบน — สมมติฐาน — ยังไม่ยืนยัน)
- ผลสั้นแบบ structured: `PASS` หรือ `FAIL` + รายการ `REV-NNN` แต่ละข้อมี Severity, Task, Location (file:line), Problem, Reference (DES/REQ)

- **AC-049** — review session มี session ต่างจาก implementer ทุกตัวใน wave และ packet ไม่มี conversation/reasoning ของ implementer
- **AC-050** — ผล review มี verdict `PASS` หรือ `FAIL`; finding ทุกข้อมี REV-NNN, Severity, Task, Location (file:line), Problem, Reference — ผลที่ขาดฟิลด์ ระบบไม่รับเป็นผล review
- **AC-051** — task ที่ใหญ่ตามค่า config หรือมี flag security-sensitive ใน plan ถูก review ใน session ของตัวเอง ไม่รวมกับ wave อื่น; ไม่มี wave ใดเกินค่าเพดานจำนวน task/diff ใน config และทุก task ใน wave อยู่ phase เดียวกัน
- **AC-052** — write audit ไม่พบไฟล์ใน code root ที่ถูกแก้โดย reviewer session
- **AC-080** — ทุก review/security session ใน log ไม่อ้างแถว task ที่ Owner = reviewer/security; security session เกิดเฉพาะ phase ที่มี task 🔒 และหลัง QA ของทุก task ใน phase นั้น (ลำดับ pipeline ใน `CLAUDE.md`)
