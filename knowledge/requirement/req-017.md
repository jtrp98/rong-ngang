# REQ-017 — Feature / Integration QA หลัง task ของ feature ครบ

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น

## กติกาทางธุรกิจ

- task ผ่านครบทุกตัวไม่ได้แปลว่า feature รวมผ่าน → หลัง task ทั้งหมดของ feature verified ต้องมี **Feature/Integration QA** ทดสอบ complete user flow
- feature ยังไม่นับว่าผ่าน และยังไม่ไป security/deploy จนกว่า Feature QA PASS
- feature = **phase** ใน `plan\index.md` — PM ต้องแบ่ง phase เป็นชิ้นที่ user flow จบในตัว (OQ-13 — เจ้าของ jtrp98 2026-10-05)
- Feature QA FAIL ที่ระบุ task ได้ → defect packet ไป owner ของ task นั้น (รูปเดียวกับ REQ-016) และนับเข้าตัวนับ retry ของ task นั้น (REQ-021) · ระบุ task ไม่ได้ → ขึ้น Waiting on Human และไม่นับ retry
- user flow ที่ทดสอบ มาจาก TP เมื่อ feature มี test plan; ไม่มี → QA ดึงจาก REQ/AC ของ task ใน phase

- Source: เจ้าของ (jtrp98) — spec ข้อ 23, 30 ผ่าน driver 2026-10-05 · Confirmed by: เจ้าของ (jtrp98) 2026-10-05 · Status: confirmed
- **AC-057** — เมื่อ task ทุกตัวใน phase เดียวกันเป็น verified ระบบเปิด Feature QA เอง และ security/deploy ของ feature นั้นไม่เริ่มจนกว่า Feature QA PASS
- **AC-058** — ผล Feature QA ระบุ user flow ที่ทดสอบ (อ้าง TP ถ้า feature มี test plan, ไม่มีอ้าง REQ/AC) พร้อมผลต่อ flow
- **AC-077** — Feature QA FAIL ที่ไม่ระบุ task: ขึ้น Waiting on Human, ไม่มี dispatch แก้อัตโนมัติ และตัวนับ retry ของ task ใน phase ไม่เปลี่ยน
