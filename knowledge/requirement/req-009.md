## กติกาทางธุรกิจ

อ่าน git ได้เสมอ สวิตช์ใน `sta-config` (ต่อ knowledge, override ต่อ target) เป็น permission ให้ AI ที่ใช้เครื่องมือนี้ commit ได้ — ระบบไม่ commit เอง ไม่กำหนดจังหวะ/ขอบเขต · commit อย่างเดียว push/branch/merge ยังห้าม · สวิตช์ปิด = กติกา no state-changing git เดิม · default เปิด · สลับด้วย slash command `/gituse` ของ coding agent (solo mode) ซึ่งแก้ `sta-config` ใครก็สลับได้ ไม่ต้องบันทึกประวัติ · มีผล run ถัดไป · write audit ไม่ขึ้นกับสวิตช์ · ไม่มี field `git.remote` ไม่ตรวจ origin

- Source: ผู้ใช้ 2026-10-05 ผ่าน AskUserQuestion (verbatim ใน `..\open-questions\oq-7.md`, `oq-8.md`, `oq-9.md`) · Confirmed by: ผู้ใช้ · Status: confirmed — รวมข้อยกเว้น "เปิดอยู่ = ระบบ commit ได้ (กติกาเดิมใช้เมื่อสวิตช์ปิด)"
- **AC-025** — สวิตช์อยู่ใน `sta-config` ตั้งได้ต่อ knowledge และต่อ target; target ที่ตั้งไว้ชนะ knowledge
- **AC-026** — ไม่ว่าสวิตช์เป็นค่าใด ระบบอ่าน git ได้ และ write audit ใช้ git diff เมื่อ root เป็น repo
- **AC-027** — สวิตช์ของ root ใดปิด ไม่มี commit เกิดที่ root นั้นจาก AI/role ใดตลอด run
- **AC-028** — ไม่ได้ตั้งค่าทั้ง knowledge และ target = สวิตช์เปิด
- **AC-029** — สั่ง `/gituse` ใน coding agent แล้วค่าใน `sta-config` เปลี่ยน; run ที่วิ่งอยู่ใช้ค่าเดิมจนจบ; run ถัดไปใช้ค่าใหม่
- **AC-030** — สวิตช์เปิด: AI commit ที่ root นั้นได้; push/branch/merge ยังถูกปฏิเสธ; orchestrator ไม่ commit เอง
- **AC-031** — สวิตช์เปิดแต่ root ไม่ใช่ git repo: แสดงคำเตือนแล้วข้าม commit โดย run ไม่ล้ม
- **AC-032** — `sta-config` ไม่มี field `git.remote` และไม่มีการตรวจ origin
