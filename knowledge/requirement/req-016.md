# REQ-016 — QA: clean session ต่อ QA round, batch checks, defect packet

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น

## กติกาทางธุรกิจ

- QA verify implementation จริงเทียบ requirement + acceptance ใน **clean session**
- อ่าน: task, REQ, test cases, review result ที่จำเป็น, implementation จริง, runtime/test env (+ shared system artifact เช่น data model เมื่อจำเป็น)
- **batch ต่อ execution wave / QA round**: รัน shared checks (typecheck/lint/build/test) ครั้งเดียวต่อรอบ แล้วรายงานแยกราย task (verified/blocked ต่อ task)
- QA FAIL → ส่งกลับไป task owner เฉพาะ **defect packet**: Task, Finding `QA-NNN`, Expected, Actual, Reproduce (`TP-NNN`), Evidence — ไม่ส่ง conversation ของ QA

- **AC-053** — QA session ต่างจาก session ของ implementer และ reviewer และ packet ไม่มี conversation ของทั้งสอง
- **AC-054** — QA round ที่มีหลาย task: shared checks ถูกรันครั้งเดียวต่อรอบ (ดูจาก log) และผลรายงานแยกราย task
- **AC-055** — task ที่ FAIL ได้ defect packet ที่มีครบ Task, QA-NNN, Expected, Actual, Reproduce (TP-NNN ถ้ามี), Evidence และ session แก้ของ owner ได้รับเฉพาะ packet นี้
- **AC-056** — task ที่ PASS ในรอบเดียวกันได้ `verified` โดยไม่ต้องรอ task ที่ FAIL
