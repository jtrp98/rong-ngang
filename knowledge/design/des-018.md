# DES-018 — Deterministic router: output state → ขั้นถัดไป + retry counter

> Budget ≤ 8 KB · เขียนโดย `system-analyst` · 1 contract · แถวใน `design\index.md`

- **Traces:** REQ-021 (AC-068, AC-069, AC-070, AC-071, AC-076), REQ-019 (AC-062, AC-063, AC-064), REQ-016 (AC-055, AC-056), REQ-017 (AC-077), REQ-020 (AC-067, AC-075), REQ-006 (AC-078), REQ-011 (AC-073, AC-079), REQ-015 (AC-080)
- **Rule:** router = pure function `src/core/router` — `route(event, tasks, config) → Decision` ไม่มี I/O ไม่เรียก LLM (AC-067/069) · input = handoff-v2 ที่ผ่าน schema หรือ event ของ orchestrator · ทุก decision log 1 บรรทัด `{ruleId, taskId, from, to, reason}` ที่ `runs/<runId>/router.log`
- **State ที่รับได้ต่อ session kind** (นอกชุด → R15):

| kind | states |
|---|---|
| `execution` (BE/FE/setup/uxui/devops/test-planner) | DONE BLOCKED NEEDS_DESIGN_CHANGE NEEDS_REQUIREMENT_CHANGE NEEDS_HUMAN |
| `change` (BA/SA/PM — pre-plan หรือ blocker chain) | DONE BLOCKED NEEDS_HUMAN (+ SA: NEEDS_REQUIREMENT_CHANGE) |
| `review` `qa` `feature-qa` `security` (anchor = `feature-qa`) | PASS FAIL BLOCKED NEEDS_HUMAN |
| `record-only` (DES-008) | DONE BLOCKED |

- **รูป blocker (เลือกรูปเดียว):** `NEEDS_DESIGN_CHANGE` / `NEEDS_REQUIREMENT_CHANGE` + `blocker{type,task,reference,reason}` = `BLOCKED / DESIGN_CHANGE_REQUIRED` / `REQUIREMENT_CHANGE_REQUIRED` ของ REQ-019 · `BLOCKED` ใช้เฉพาะ type environment|dependency|access|other
- **ตาราง (ruleId ตายตัว — test ครอบทุกแถว):**

| ruleId | เมื่อ | ผล |
|---|---|---|
| R1 | execution DONE + audit สะอาด (DES-021) | `awaiting-review` |
| R2 | audit violation | hold `audit-violation` ทุก suspect · ไม่นับรอบ |
| R3 | review perTask PASS | `awaiting-qa` |
| R4 | review FAIL · QA blocked · Feature-QA FAIL ระบุ task — `fixRounds < fixRoundLimit` | `fixRounds++` · (QA/Feature-QA) Status `blocked` · execution session ใหม่ + defect packet (DES-019) |
| R5 | เหมือน R4 แต่ `fixRounds == fixRoundLimit` | (QA/Feature-QA) Status `blocked` · hold + gate 4 `qa-critical` (fail ครั้งที่ 3) ไม่ dispatch |
| R6 | QA perTask verified | Status `verified` (คัดจาก verdict — DES-007) · unlock dependents |
| R7 | QA defect severity Critical | Status `blocked` + gate 4 ทันที |
| R8 | Depends ครบ / ไม่ครบ (DES-001) | `runnable` / `waiting-deps` |
| R9 | Depends อ้าง id ไม่มี / วงวน | hold `dep-error` task ในวง + dependents (AC-039) |
| R10 | NEEDS_DESIGN_CHANGE (`reference` = DES-id) | hold `design-change` + dependents · คิว change: SA → PM → R13 |
| R11 | NEEDS_REQUIREMENT_CHANGE (`reference` = REQ/AC-id) | hold `requirement-change` · คิว BA ก่อนเสมอ (AC-063) → `nextRole` ของ BA (SA\|PM\|none) · SA ตามด้วย PM เสมอ |
| R12 | NEEDS_HUMAN | gate ตาม `questionsForHuman[].gate` (DES-008) · SA ส่ง `gate: none` → `touchesSchemaOrContract` true = gate 2 / false = gate 1 (AC-078) |
| R13 | PM DONE ใน change chain | task ใน `impactedTasks` ที่ไม่ verified → session ใหม่ (ไม่นับรอบ) · task ต้นเรื่องนอก impact → กลับ step เดิม · verified ใน impact → hold `reopen-needed` |
| R14 | BLOCKED | hold `blocked` · ไม่นับรอบ |
| R15 | handoff ไม่ผ่าน schema / ไม่มี outputState / state นอกชุด / ขัดกันเอง | hold `invalid-handoff` แจ้ง dashboard (AC-068) |
| R16 | crash / timeout / interrupted — `crashRestarts < crashRestartLimit` | `crashRestarts++` · session ใหม่ + `priorSession.touchedFiles` · fixRounds คงเดิม |
| R17 | crash ครบ limit | hold `crash-limit` (AC-075) |
| R18 | ทุก task ใน phase verified (ไม่นับ anchor = Owner qa-engineer และ dependents ของ anchor — DES-019) · ไม่มีแถว hold `plan-error` ใน phase | คิว `feature-qa` · `taskIds` = anchor (ไม่มี = ว่าง) |
| R19 | Feature QA PASS | anchor Status `verified` · phase มี 🔒 (นิยาม DES-019 §Security stage) → คิว `security` (stage ท้าย phase ไม่ใช่ task — AC-080) · ไม่มี → phase `cleared` |
| R20 | Feature QA FAIL ไม่ระบุ task | hold phase `feature-qa-unattributed` · fixRounds คงเดิม (AC-077) |
| R21 | security PASS / FAIL มี Critical\|Important | phase `cleared` / gate 5 |
| R22 | gate answered | record-only (DES-008) · task ที่ hold เพราะ gate → step เดิม · gate 4 → ค้างจนคนกด `retry` (DES-009) หรือ PM replan |
| R23 | handoff qa/feature-qa มี `securityGate` ไม่ว่าง (G2-f) | `securityMarks[{phase, reason}]` → orchestrator เพิ่ม 🔒 ที่ Phase (DES-007) · ประมวลร่วมกับแถวของ outputState ไม่ hold ไม่นับรอบ · phase ≠ `planPhase` ของ packet → R15 |
| R24 | แถว Owner `reviewer`/`security` (AC-079) · anchor > 1 ใน phase (DES-019) | hold `plan-error` (ref `owner:<role>` / `multi-anchor`) แถวนั้น + dependents · ไม่ dispatch · คำเตือนพร้อม task id (issue validator DES-014 + hold บน dashboard) · task อื่นเดินต่อ (แบบ R9) |

- **Localized retry (AC-070):** decision แตะเฉพาะ taskId ใน event (+ dependents เมื่อ hold) · batch ที่ task หนึ่ง FAIL — task อื่นไปตาม verdict ของตัวเอง (AC-056)
- **ตัวนับ:** `fixRounds` ตัวเดียวต่อ task (review+QA+Feature-QA) · `crashRestarts` แยก · `retry` ของคนไม่ reset — fail ถัดไปเข้า R5
- **Severity (REV/QA/security ชุดเดียว — data-model):** `Critical|Important|Minor` · blocking = Critical|Important · Minor → `backlog.md` (finish rules) · review perTask FAIL ⇔ มี finding Critical|Important ของ task ≥ 1 (ไม่ตรง → R15) · review Critical ไม่เข้า R7 (gate 4 = QA) → R4/R5
- **Inputs / Outputs:** in `RouterEvent {kind: handoff|crash|timeout|interrupted|plan-changed|gate-answered|human-retry, sessionId, taskIds[], handoff?}` · out `Decision {ruleId, transitions[{taskId, step, hold?}], dispatch[{kind, role, taskIds}], statusWrites[{taskId, value}], securityMarks[{phase, reason}], gates[]}` — type ที่ data-model
- **Permissions / States / Errors:** router ไม่เขียนไฟล์ — scheduler (DES-001) apply · verdict ขัด §Severity → R15
- **Compatibility:** แทนการนับรอบจาก StageRecord เดิม — ไม่มีโค้ด build แล้วที่ใช้
- **Data/schema · Migration:** `TaskRuntime` + handoff-v2 (data-model) — ใหม่
- **Security:** เชื่อ handoff หลังผ่าน schema เท่านั้น · agent ข้าม gate ไม่ได้ (state นอกชุด = R15)
- **Fallback:** event ไม่ตรงแถวใด → R15
