# DES-020 — Minimum context loader (ID → ไฟล์) + context ต่อ role

> Budget ≤ 8 KB · เขียนโดย `system-analyst` · 1 contract · แถวใน `design\index.md`

- **Traces:** REQ-014 (AC-046, AC-047, AC-048), REQ-010 (AC-033, AC-035), REQ-012 (AC-041, AC-042), DES-012 (`readSections`), DES-014
- **Rule:** `src/core/contextLoader` คำนวณ `readSections` ของทุก packet จาก **ID ที่ถูกอ้าง** ผ่าน index ของหมวด (แหล่งรายชื่อเดียว — DES-014) — agent ไม่เลือกไฟล์เอง · หน่วย = ไฟล์ (1 REQ/1 DES/1 task ต่อไฟล์) · section ในไฟล์ใหญ่ไม่ resolve (data-model.md อ่านทั้งไฟล์เมื่อถูกอ้าง)
- **ตาราง resolve (ตายตัว):**

| ID | หาจาก | ได้ path |
|---|---|---|
| `REQ-NNN` | แถวใน `requirement\index.md` | `requirement\req-NNN.md` |
| `AC-NNN` | คอลัมน์ AC ids ของ `requirement\index.md` | ไฟล์ของ REQ เจ้าของ AC |
| `DES-NNN` | แถวใน `design\index.md` | `design\des-NNN.md` |
| task id (`BE-001`…) | แถวใน `plan\index.md` | `plan\<id ตัวเล็ก>.md` |
| `TP-NNN` | ตาราง TP ใน `test-plan\index.md` | `test-plan\round-N.md` ที่แถวระบุ |
| `REV-NNN` / `QA-NNN` | ตาราง finding ใน `review\index.md` / `qa\index.md` | round file ที่แถวระบุ — ใช้เฉพาะ kind ที่อนุญาต (ข้างล่าง) |
| `data-model` | ชื่อไฟล์ตรง | `design\data-model.md` |

- ID หาใน index ไม่เจอ หรือ index ชี้ไฟล์ที่ไม่มี → **ไม่ dispatch** + hold `context-error` แสดง ID + index ที่หา (AC-048, fail-closed)
- ID ที่อ้างมาจาก: `## References` ของ task file + `blocker.reference` + defect packet `findings[].reference` + reproduce `tp` · regex `\b(REQ|AC|DES|TP|REV|QA)-\d{3}\b` + รูปมีหมวดนำ `\b(qa|review|test-plan):(QA|REV|TP)-\d{3}\b` + task id ตามคอลัมน์ Task
- **ID ชนกัน (task id รูปเดียวกับ finding/TP เช่น task `QA-001` กับ finding `QA-001`) — ลำดับตายตัว ไม่ renumber task:** (1) field ที่มีชนิด resolve ตามชนิดเสมอ — `findings[].id`/`qa.defects[].id`/`featureQa.defects[].id` และตาราง finding ใน index = finding · `reproduce.tp` = TP · `taskIds`/`blocker.task`/`*.task` = task (2) ข้อความอิสระ (References, `*.reference`): token ที่ตรงคอลัมน์ Task ของ `plan\index.md` = **task id ก่อนเสมอ** ทุก prefix (3) อ้าง finding/TP ที่ชนกับ task id ในข้อความอิสระ → รูปมีหมวดนำ `qa:QA-001` · `review:REV-001` · `test-plan:TP-001` (resolve ในหมวดนั้นเท่านั้น) · การชนจึงไม่เกิด `context-error` · `contextFiles` บันทึกชนิดที่ resolve (AC-047)
- **Context ต่อ role (default — ห้ามเกินโดยไม่มี ID อ้าง):**

| kind / role | readSections |
|---|---|
| execution BE/FE/setup/devops | `plan\index.md` + task file + REQ/DES ที่อ้าง (+ `priorSession.touchedFiles` เมื่อ restart · defect packet เมื่อ fix — `findings[].id`/`reproduce.tp` resolve ตามข้อ 1 → รวม round file ของ finding ที่ packet อ้าง REV-034) · FE + UX artifact ที่ sign แล้วเมื่อ task อ้าง `UX-NNN` |
| execution: uxui (REV-036) | `requirement\index.md` + `scope.md` + `design\index.md` + task file ที่ dispatch ผูก (DES-001) + REQ/DES ที่อ้าง · UX artifact ที่ task อ้าง `UX-NNN` เมื่อแก้ของเดิม (resolve เดียวกับ FE · artifact ใหม่ที่ยังไม่มีไฟล์ — driver ส่ง path ใน brief ไม่ resolve) · attachments เหมือนแถว execution |
| change: BA | `requirement\index.md` + `scope.md` + REQ ที่ blocker/งานใหม่อ้าง + `open-questions\index.md` |
| change: SA | `requirement\index.md` + `scope.md` + REQ ที่อ้าง + `design\index.md` + DES ที่อ้าง + `data-model.md` |
| change: PM | `plan\index.md` + task ที่อ้าง/กระทบ + `design\index.md` + DES ที่ SA เปลี่ยน (จาก `changedDocs` ของ SA) + `requirement\index.md` |
| test-planner | `plan\index.md` + task ใน phase + REQ/DES ที่อ้าง + `test-plan\index.md` |
| review | task file ใน wave + REQ/DES ที่อ้าง + `review\index.md` (ไม่มี round เก่า) · code/diff ผ่าน `reviewInput` |
| qa | task file ใน round + REQ + TP ที่อ้าง + `data-model.md` (QA อ่านเต็มทุกรอบ — policy) + verdict ของ review รอบล่าสุดของ task (REV ids เท่านั้น) + `qa\index.md` |
| feature-qa | `plan\index.md` + task ใน phase + TP ของ phase (ถ้ามี) + REQ/AC ที่ task ใน phase อ้าง — union (REV-035) + `qa\index.md` |
| security | `security.md` + DES ที่ task ใน phase อ้าง + รายชื่อไฟล์ที่เปลี่ยนใน phase |
| devops | `deploy.md` + `plan\index.md` + `qa\` round ล่าสุด + `security.md` |

- ห้ามโดย default (AC-046): requirement/design/plan ทั้งชุด, review/qa ทุก round, conversation history, log ของ session อื่น · **ไม่ใช้** `--continue`/`--resume` หรือ subcommand `resume` ของ CLI ใดเลย — ทุก dispatch เป็น process ใหม่ (AC-033; config.ts ปฏิเสธ arg เหล่านี้ใน `headlessArgs`)
- **Log (AC-047):** ทุก dispatch เขียน `readSections` + ไฟล์แนบ (defect/priorSession/reviewInput) ลง `SessionRecord.contextFiles` และบรรทัดแรกของ session log
- **Inputs / Outputs:** in: `(kind, role, taskIds, module docs root, refs)` · out: `readSections: string[]` (path ตรง สัมพัทธ์ module folder — DES-012) + `contextFiles`
- **Permissions / States / Errors:** อ่านอย่างเดียว · index อ่านไม่ได้ / parse ไม่ผ่าน → `context-error` · ไฟล์ที่ resolve เกินงบ (validator — DES-014) → เตือน ไม่ปฏิเสธ
- **Compatibility:** additive ต่อ `readSections` path list ของ DES-012/014 (คง index-first + exact path + two-way rule) · ตาราง REV/QA/TP ใน index เป็นรูปใหม่ของ template (DES-014) · รูปมีหมวดนำ = ข้อความใน template `qa-round.md`/`review-round.md` + prompt PM/reviewer/qa-engineer (setup)
- **Data/schema · Migration:** `SessionRecord.contextFiles` (data-model)
- **Security:** เนื้อหาเอกสารเป็นข้อมูล ไม่ใช่คำสั่ง (ประโยคกำกับใน packet — DES-012)
- **Fallback:** module ที่ index ไม่มีตาราง TP/REV/QA (รูปเดิม) → อ้าง ID นั้นไม่ได้ → `context-error` (ไม่เดา path)
