# DES-021 — Write audit ต่อ session (parallel) ด้วย path claim

> Budget ≤ 8 KB · เขียนโดย `system-analyst` · 1 contract · แถวใน `design\index.md` · ทางเลือก B ยืนยันโดยเจ้าของ (jtrp98) 2026-10-05 (gate 2)

- **Traces:** REQ-013 (AC-043, AC-045), REQ-003 (AC-007), REQ-011 (AC-073), REQ-015 (AC-052), REQ-018 (AC-060), REQ-020 (AC-066), DES-006 (ชั้น 3)
- **ปัญหา:** audit เดิม = snapshot ก่อน/หลัง stage ทั้ง root — session พร้อมกันบน working tree เดียว diff ปนกัน · `git status` เดิมนับไฟล์ dirty ค้างจาก stage ก่อนเป็นของ stage ใหม่
- **Rule (ทางเลือก B — แนะนำ):**
  1. **Claim:** ทุก session ได้ `claim: string[]` ก่อน dispatch — รูปที่รับมีสองแบบเท่านั้น: path ไฟล์ตรง หรือ `<dir>/**` (สัมพัทธ์ root) · engineer: จาก `- Write paths:` ใน `## Scope` ของ task file (DES-014) ต้องอยู่ใต้ `writeScope.allow` ของ role ไม่งั้น task hold `plan-error` · ไม่ระบุ → claim = allow ทั้งหมดของ role (= `codeRoots/**`) · role เอกสาร: claim = allow ของ role (module-scoped)
  2. **Overlap = prefix:** สอง claim ชนกันเมื่อ path หนึ่งเป็น prefix ของอีก path (หรือเท่ากัน) · scheduler (DES-001) **ไม่เริ่ม session ที่ claim ชนกับ session ที่กำลังรัน** — รอคิว · ผล: engineer ที่ไม่ระบุ Write paths รันทีละตัวต่อ codeRoot แต่คู่ขนานกับ role เอกสารได้ · reviewer/QA ต่อ module ทีละ session (ชน `review/**`, `qa/**` ตัวเอง)
  3. **Snapshot:** ตอนเริ่ม session บันทึก `{path → sha256}` ของไฟล์ไม่ถูก ignore ทุก root ของ run (git root: `git ls-files -co --exclude-standard`; non-repo: เดินไฟล์ลบ `audit.manifestIgnore`) ลง `sessions/<sid>/snapshot.json` (persist — ใช้หลัง crash) + pre-image ของไฟล์ใต้ claim (เพดาน `audit.preimageMaxMB`) + pre-image `plan/index.md` เสมอ · ตอนจบ snapshot อีกครั้ง → `changed` = path ที่ hash ต่าง/เกิด/หาย
  4. **Attribution:** f ∈ changed → ใต้ claim ตัวเอง = ของ session นี้ (`touchedFiles`) · ใต้ claim ของ session อื่นที่ active ทับช่วงเวลา = ข้าม (ของ session นั้น) · ตรง self-write journal ของ orchestrator (path + hash หลังเขียน) = ข้าม · นอกนั้น = **violation** `unclaimed-write` พร้อม `suspects` = session ทุกตัวที่ active ทับช่วงและไม่ claim f → R2 (DES-018) hold ทุก suspect (fail-closed, dedupe ด้วย path+hash)
  5. **Status column (AC-073):** parse ตาราง Tasks ของ pre/post `plan/index.md` — session ใดเปลี่ยนค่า Status ของแถวที่มีอยู่ = violation `status-write` (รวม qa-engineer) · แถวใหม่โดย PM ต้องเป็น `pending` · ค่านอก pending|verified|blocked = violation · **ลบแถว (pin REV-040 — review round 15):** PM ลบแถวออกจากตาราง Tasks ระหว่าง replan = ได้ (โครงตารางเป็นพื้นที่ของ PM — เอกสารชนะ, DES-007 §Resume) · role อื่นลบแถว = violation `status-write` ตามเดิม (fail-closed — engineer align `session-audit.ts:642-645` ที่จับ PM ด้วย)
  6. **Diff สำหรับ review/size:** `git diff --no-index --numstat <pre-image> <file>` (read-only, ใช้ได้นอก repo — ต้องมี git binary: Git Bash ตาม scope.md Constraints) · ไม่มี pre-image (เกินเพดาน) → `git diff HEAD --numstat -- <file>` + `diffApprox: true` (นับเกิน = ปลอดภัย: แยก review มากขึ้น)
  7. คง ref audit + git ต่อ role (DES-016) · ไม่ auto-revert เหมือนเดิม
