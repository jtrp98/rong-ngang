## DES-010 — งานใหม่ส่งตรงถึง business-analyst

**Traces:** REQ-007 (AC-017, AC-018, AC-019), REQ-001

**Rule:** `POST /api/tasks/new` สร้าง run mode=new-work ที่ stage แรก = dispatch business-analyst ทันที (ไม่มีชั้นจัดหมวด — ตัดสินใจแล้วใน requirement) packet ของ BA มี: ข้อความดิบครบทุกตัวอักษร (AC-017) + บรีฟบังคับหน้าที่ BA ตาม role prompt เดิม (สัมภาษณ์เมื่อข้อมูลไม่ครบ / normalize เมื่อครบ) + กติกาที่ BA ต้องตัดสินเอง: เพิ่มเข้า module เดิม (amend requirement) หรือสร้าง module ใหม่ (สร้าง folder + requirement.md จาก template — BA เป็น role เดียวที่สิทธิ์สร้าง module folder ตาม `policies\documentation.md:5,17`) — **ห้าม driver/ระบบตัดสินแทน** (อย่าคิดแทน business rule) หลัง BA จบ: handoff `decision` ถูกแสดงบน UI ทันที (AC-018) แล้ว driver เดิน process เดิมต่อเอง (SA → PM → …) จนถึง gate ถัดไป (AC-019) — การสัมภาษณ์เพิ่มของ BA กลาง stage ไม่ทำได้เพราะ CLI headless ไม่มี AskUserQuestion จริง → คำถามที่ BA ต้องถามกลายเป็น `questionsForHuman` → gate business-choice ตอบผ่าน UI แล้วบรีฟรอบถัดไปฉีดคำตอบ (นี่คือการเชื่อม AskUserQuestion เดิมเข้ากับ gate กลไกเดียวกัน)

**Inputs/Outputs:** Input: ข้อความดิบ. Output: run + BA stage; หลัง BA: module ปลายทาง (เดิม/ใหม่) ปรากฏใน run.json และ pointer ของ module นั้นถูกสร้าง · **Permissions/States/Errors:** ข้อความว่าง/เกินลิมิต → 400 ก่อนสร้าง run; BA สร้าง module ชนกับชื่อที่มีอยู่ → ผ่านกติกาเดิมของ BA (ถามผู้ใช้) ซึ่งกลายเป็น gate · **Compatibility:** additive · **Data/schema · Migration:** ไม่มี · **Security:** ข้อความเป็น untrusted — ดู DES-009 Security; ต้องผ่านเฉพาะเป็นข้อมูล · **Fallback:** ถ้า BA ตัดสิน "ต้องข้อมูลเพิ่ม" โดยไม่สร้าง/amend → คำถามกลายเป็น gate รอเจ้าของ (ไม่ตกไปไหน ไม่เดา)
